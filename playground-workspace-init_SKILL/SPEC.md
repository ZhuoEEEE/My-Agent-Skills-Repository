# playground-workspace-init Skill 设计交接

## 状态

- 本目录保存已讨论确认的 Skill 设计，不是可直接安装的 Skill。
- 实际 Skill 将在其他对话中创建、验证和安装。
- 建议 Skill 名称：`playground-workspace-init`。
- 建议调用方式：仅显式调用，关闭隐式调用。

## 目标

初始化或升级用于短会话、短生命周期和多主题任务的工作区，隔离不同对话产生的文件、脚本、依赖和中间产物，避免内容堆积在工作区根目录或被其他对话误认领。

本 Skill 只负责初始化、升级和维护工作区规范，不负责具体话题任务。初始化或升级完成后，由工作区根目录的 `AGENTS.md` 约束后续新对话和续接对话。

## 适用与不适用范围

适用于：

- 临时研究、资料整理、工具试验和短期脚本。
- 同一根目录中并存多个相互独立的话题。
- 需要通过话题说明恢复旧对话上下文的工作区。
- 已存在内容的 Playground 工作区首次接入本规范，或从旧版规范升级到当前 Skill 携带的最新版规范。

不适用于：

- 为 IDE 生成的正式嵌入式工程规定源码结构。
- 自动重构、搬迁或归档既有项目源码。
- 自动初始化 Git、创建分支、提交或推送。

## 显式调用策略

在 `agents/openai.yaml` 中设置：

```yaml
policy:
  allow_implicit_invocation: false
```

示例调用：

```text
$playground-workspace-init 初始化当前多主题工作区，保持现有内容不变。
```

在支持 `@` 选择 Skill 的界面中，可通过界面显式选择该 Skill。未被用户显式选择或提及时，不应自动执行初始化。

## 初始化后的根目录

```text
<workspace>/
|-- AGENTS.md
|-- README.md
|-- workspace-management/
|   `-- README.md
`-- YYYY-MM-DD-undetermined-topic[-N]/
    `-- README.md
```

- `AGENTS.md`：后续对话自动读取的强制管理规则。
- 根 `README.md`：工作区用途、目录约定和话题索引。
- `workspace-management/`：固定用于工作区管理，不带日期。
- 话题目录：各对话的过程文件和说明。

## 初始化行为

1. 先检查工作区现状、已有文件、目录和 Git 状态，判断属于首次初始化、旧版升级还是已为最新版。
2. 不覆盖已有 `AGENTS.md` 或 `README.md`；存在时应读取并进行最小合并，实质冲突必须向用户确认。
3. 创建缺失的全局规则和管理目录；升级时只更新由本 Skill 管理的规则，不接管用户内容。
4. 纯初始化、升级和工作区维护对话使用 `workspace-management/`，不额外创建日期话题目录；开始处理具体话题任务时才创建对应话题目录。
5. 不主动整理、移动、重命名或删除初始化前已存在的文件。
6. 不主动初始化 Git，也不自动暂存、提交、切换分支或推送。
7. 完成后验证必要文件存在、内容可读、规则没有重复，并汇报实际新增、更新和保留项。

## 已有工作区升级与幂等

可以在已有 Playground 工作区中显式调用本 Skill，将其初始化或升级到当前 Skill 携带的最新版规范。建议调用：

```text
$playground-workspace-init 将当前 Playground 工作区升级到最新版规范，保留已有文件、目录和用户规则。
```

- 模板生成的 `AGENTS.md` 规则和根 `README.md` 话题索引应使用带规范版本的托管区块标记，使后续升级能够准确识别本 Skill 管理的内容。
- 托管区块之外的用户内容必须原样保留；升级只替换对应托管区块，不得整份重写文件。
- 已有文件没有托管区块时，由模型读取内容并进行一次最小语义合并，避免重复规则；不能由脚本根据字符串匹配盲目覆盖。
- 已经符合最新版规范时，重复调用应保持幂等，不重复插入规则、索引、目录或 README 内容。
- 发现实质冲突时，先向用户说明冲突和最小处理选项；在用户确认前保留原内容。
- 既有目录即使不符合新命名规范，也不自动迁移或重命名；只记录现状，后续新目录遵循最新版规范。

推荐的托管区块形式如下，实际模板可按文件职责使用不同区块名称：

```markdown
<!-- playground-workspace-init:managed:start version="1" -->
由本 Skill 管理的内容
<!-- playground-workspace-init:managed:end -->
```

## 新对话规则

- 每个新对话在处理首个任务前创建一个全新的独立目录和其中的 `README.md`，即使首个任务尚未生成其他文件也一样执行。
- 初始目录名为 `YYYY-MM-DD-undetermined-topic/`，日期使用对话创建当天的本地日期。
- 同名目录存在时，使用最小可用序号：`-2`、`-3`，依次递增。
- 创建目录时采用“尝试原子创建，冲突后重新计算序号”的方式，避免并发对话选中同一名称。
- 新对话不得复用、认领、移动或重命名任何已有目录作为自己的目录。
- `workspace-management/` 是唯一固定例外，仅供纯初始化、升级和工作区管理对话使用。

## 续接旧对话规则

- 继续旧对话时，根据对话上下文和话题 `README.md` 定位并复用原目录。
- 重新打开、继续消息或对话运行多轮，不代表新话题，不创建重复目录。
- 无法可靠确定原目录时，在写入或移动文件前询问用户，不得猜测或认领相似目录。

## 主题确定与重命名

- 持续识别用户指令“将该对话主题定为 xxxx”及语义等价的明确指令。
- 将主题概括为简短、清晰的英文 kebab-case。
- 只允许重命名当前对话自己的目录，不得修改其他对话目录。
- 目标名称采用 `YYYY-MM-DD-topic/`；冲突时追加最小可用序号。
- 重命名后保留全部内容，并同步更新当前目录的 `README.md` 和根 `README.md` 话题索引。
- 普通话题演变不应频繁触发目录重命名；没有明确要求时只更新 `README.md`。

## 话题 README 最低内容

每个话题目录的 `README.md` 至少记录：

- 创建日期。
- 可用时记录对话或任务标识；不可用时记录创建时间和初始目录名，用于辅助确认归属。
- 当前话题。
- 目标或用途。
- 主要文件和产物。
- 当前状态。
- 未处理事项。
- 继续该话题时需要的入口信息。

状态、产物或未处理事项发生变化时，应在任务结束前更新。

## 文件放置规则

- 当前对话新建、复制、下载或生成的文件，以及一次性工具、脚本、依赖和中间产物，放入当前话题目录。
- 当前对话生成的工具和脚本须按类型或用途分类，放入当前话题目录下对应的专用子目录，不得堆放在话题目录根目录。
- 单文件或一次性脚本默认放入 `scripts/`；多文件工具默认放入 `tools/<tool-name>/`；依赖和配置跟随对应脚本或工具存放。只创建当前任务实际需要的子目录，不预建空目录。
- 既有项目文件继续在原路径修改，不得为了对话归档而搬入话题目录。
- 工作区外的原始资料只读取；需要副本时复制到当前话题目录。
- 根目录仅保留 `AGENTS.md`、全局 `README.md`、话题目录和用户明确指定的跨话题共享内容。
- 新增、删除或重命名话题目录时，同步维护根 `README.md` 的话题索引。

## 安全边界

以下限制只约束本 Skill 执行的初始化、升级、话题归属和目录管理操作，不限制后续具体任务中由用户明确授权的正常文件或进程操作。

- 不删除文件。
- 不移动归属不明或属于其他话题的内容。
- 不重置、清理或改写 Git 历史。
- 不停止正在运行的服务或工具。
- 不覆盖用户已有的未提交修改。
- 文件移动可能破坏路径、依赖或运行状态时，保持原样并在话题 `README.md` 中记录。
- 需要超出初始化和目录管理范围的操作时，先取得用户确认。

## 完成前检查

- 当前对话是否拥有唯一且可确认的目录。
- 当前对话产物是否遗留在根目录。
- 当前话题 `README.md` 是否反映最新状态。
- 根话题索引是否与真实目录一致。
- 托管区块版本是否为当前版本，且没有重复区块或重复规则。
- 是否误动其他对话目录或初始化前已有内容。
- 最终回复是否列明新增、修改、移动和保留的内容。

## 建议的实际 Skill 结构

```text
playground-workspace-init/
|-- SKILL.md
|-- agents/
|   `-- openai.yaml
|-- assets/
|   |-- AGENTS.md
|   |-- workspace-README.md
|   `-- topic-README.md
`-- scripts/
    `-- init_workspace.py
```

- `SKILL.md` 保留触发边界、初始化流程和安全约束。
- 模板放入 `assets/`，避免每次重新生成关键规则。
- 初始化脚本只负责确定性地创建缺失内容、原子创建话题目录、处理名称冲突和更新已识别的托管区块；不得负责迁移既有文件或猜测无标记文档的合并方式。
- 已有无标记文档的首次接入和实质冲突处理由模型完成，脚本不得整份覆盖用户文件。
- 如果不用脚本也能保持实现简单可靠，可以省略 `scripts/`，不要为了目录完整而添加空资源。

## 验收场景

实际 Skill 创建后至少验证：

1. 空工作区能生成完整的全局规则、说明和管理目录。
2. 已有文件和未提交改动保持不变。
3. 同一天创建多个新对话时目录名称不会冲突。
4. 新对话不会认领或重命名已有话题目录。
5. 续接旧对话会复用原目录，不创建重复目录。
6. 明确定主题后只重命名当前对话目录并更新说明和索引。
7. 未显式调用 Skill 时不会执行初始化。
8. 任务结束后根目录没有当前话题遗留产物。
9. 已有 Playground 工作区能在保留用户内容和旧目录的前提下升级到最新版规范。
10. 重复初始化或重复升级不会产生重复规则、重复索引或重复管理目录。
11. 两个新对话并发创建目录时不会取得相同名称。
12. 初始化或升级中断后再次执行可以安全继续。
13. 纯工作区管理对话只使用 `workspace-management/`，不会产生空的日期话题目录。

## 创建实际 Skill 时的成功标准

- 使用 `skill-creator` 初始化并验证实际 Skill。
- Skill 名称、描述和显式调用策略相互一致。
- 规则足够明确，可以防止跨对话目录误认领。
- 不预设 Git、语言、框架或项目源码结构。
- 首次初始化、旧版升级和重复执行均保持用户内容不丢失且结果幂等。
- 模板和脚本通过最小行为测试。
- 使用 `quick_validate.py` 验证 Skill 结构和元数据。
